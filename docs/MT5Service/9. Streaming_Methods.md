# 📡 MT5Service — Streaming Methods (Mid-Level API)

> Real-time subscriptions: ticks, trade events, position profit, ticket lists and trade transactions. All five are **pure pass-through** — they forward your `StreamObserver` to `MT5Account` and return the same `Context.CancellableContext` you use to stop the stream.

**Layer:** MID — pass-through to [`MT5Account` · Subscriptions](../MT5Account/6.%20Subscriptions/Subscriptions.Overview.md).

---

## Value at a glance

| Method | Direct-use value |
|--------|------------------|
| `onSymbolTick` `onTrade` `onPositionProfit` `onPositionsAndPendingOrdersTickets` `onTradeTransaction` | ⛔ pure pass-through — identical to the `MT5Account` method of the same name |

> Because these add nothing, calling `service.getAccount().onSymbolTick(...)` is equivalent. They exist so `MT5Sugar` and `MT5Service` users have one consistent entry point.

---

## Methods

| Method | Returns | Implementation |
|--------|---------|----------------|
| `onSymbolTick(symbolNames, responseObserver)` | `Context.CancellableContext` | `account.onSymbolTick(...)` |
| `onTrade(responseObserver)` | `Context.CancellableContext` | `account.onTrade(...)` |
| `onPositionProfit(timerPeriodMilliseconds, ignoreEmptyData, responseObserver)` | `Context.CancellableContext` | `account.onPositionProfit(...)` |
| `onPositionsAndPendingOrdersTickets(timerPeriodMilliseconds, responseObserver)` | `Context.CancellableContext` | `account.onPositionsAndPendingOrdersTickets(...)` |
| `onTradeTransaction(responseObserver)` | `Context.CancellableContext` | `account.onTradeTransaction(...)` |

- Each takes a `io.grpc.stub.StreamObserver<…Reply>` with `onNext` / `onError` / `onCompleted`.
- The returned `Context.CancellableContext` stops the stream: call `ctx.close()` (or `ctx.cancel(cause)`), or close the whole channel with `service.close()`.
- `onPositionProfit` / `onPositionsAndPendingOrdersTickets` are timer-driven — you pass the push interval in **milliseconds**.

Per-stream payload fields (`getSymbolTick()`, `getEventData()`, `getAccountInfo()`, `getTradeTransaction()`, …) are documented once in the low-level pages:

- [OnSymbolTick](../MT5Account/6.%20Subscriptions/OnSymbolTick.md) · [OnTrade](../MT5Account/6.%20Subscriptions/OnTrade.md) · [OnPositionProfit](../MT5Account/6.%20Subscriptions/OnPositionProfit.md)
- [OnPositionsAndPendingOrdersTickets](../MT5Account/6.%20Subscriptions/OnPositionsAndPendingOrdersTickets.md) · [OnTradeTransaction](../MT5Account/6.%20Subscriptions/OnTradeTransaction.md)

## 🔗 Usage

```java
import io.grpc.Context;
import io.grpc.stub.StreamObserver;

MT5Service service = new MT5Service(account);

Context.CancellableContext ctx = service.onSymbolTick(
    new String[]{"EURUSD", "GBPUSD"},
    new StreamObserver<Mt5TermApiSubscriptions.OnSymbolTickReply>() {
        @Override public void onNext(Mt5TermApiSubscriptions.OnSymbolTickReply reply) {
            if (reply.hasData()) {
                var t = reply.getData().getSymbolTick();
                System.out.printf("%s: %.5f / %.5f%n", t.getSymbol(), t.getBid(), t.getAsk());
            }
        }
        @Override public void onError(Throwable e) { System.err.println("stream error: " + e.getMessage()); }
        @Override public void onCompleted() { System.out.println("stream completed"); }
    });

Thread.sleep(60_000);   // keep the main thread alive to receive events
ctx.close();            // stop this stream (or service.close() to drop the channel)
```

> ⚠️ Streams do not stop on their own — always keep the `CancellableContext` and close it, then `service.close()`. See [gRPC Channel & Stream Management](../All_Guides/GRPC_CHANNEL_AND_STREAM_MANAGEMENT_EN.md).
